# ADR-003 Phase 1: License Freemium System

## Context

Kiroku V15 所有 milestone (M0-M4) code complete，需實作 ADR-003 Phase 1 授權系統。
已有基礎：`verify.js`（Ed25519 驗證）、`machine-id.js`（指紋）、`doctor` 顯示授權狀態。
Phase 1 目標：本地 freemium 限制 + 穩定指紋 + 真正 keypair，不需伺服器。

## Freemium 規則

| | Free | Licensed |
|---|---|---|
| Facts | 500 上限，超過覆寫最冷 | 無限 |
| Embedding | 停用（文字搜尋仍可用） | 啟用 |
| 每日萃取 | 50 次/天 | 無限 |
| 啟動提示 | gentle reminder | 無 |

## 步驟

### 1. `scripts/gen-keypair.js` — 建立金鑰產生工具
- 新檔案，用 `node:crypto` 產生 Ed25519 keypair
- 輸出 `keys/public.pem` + `keys/private.pem`
- `keys/` 加入 `.gitignore`
- 執行一次產生真正 keypair

### 2. `scripts/sign-license.js` — 建立離線簽發工具
- 新檔案，讀 `keys/private.pem` + machine-id + tier + expiry
- 輸出 `base64(payload).hex(signature)` 格式的 `license.dat`
- 用法：`node scripts/sign-license.js <machine-id> [tier] [days]`

### 3. `src/license/machine-id.js` — 改用硬體級 machine ID

優先使用重裝系統也不變的硬體 ID，逐層 fallback：

| 優先級 | OS | 來源 | 重裝不變？ | 需 root？ |
|--------|-----|------|-----------|----------|
| 1 | macOS | `ioreg` IOPlatformSerialNumber | ✅ 硬體序號 | 不需要 |
| 1 | Linux | `/sys/class/dmi/id/product_uuid` | ✅ BIOS UUID | 部分 distro 不需 |
| 1 | Win32 | `wmic csproduct get UUID` | ✅ BIOS UUID | 不需要 |
| 2 | Linux | `/etc/machine-id` | ❌ 重裝會變 | 不需要 |
| 3 | 全平台 | hostname + cpus[0].model + totalmem + arch | ❌ | 不需要 |
| 4 | 全平台 | MAC + arch + platform（現有邏輯） | ❌ | 不需要 |

- 改為 `async function getMachineId()` + cache
- 保留 `getMachineIdLegacy()`（現有 MAC 邏輯，雙驗證用）
- 每層嘗試失敗時靜默 fallback 到下一層

### 4. `src/license/verify.js` — 嵌入 public key + 雙指紋
- 把 `PUBLIC_KEY` 嵌入為常數（從 `keys/public.pem` 讀取）
- 移除對 `public.pem` 檔案的依賴
- `verifyLicense()` 改為 `async`（因 getMachineId 變 async）
- 同時驗證 `payload.mid` 對 new machine-id 和 legacy machine-id

### 5. `src/shared/config.js` — 加 freemium 參數
```
license: {
  enabled: true,
  freemium: {
    factLimit: 500,
    dailyExtractLimit: 50,
    embeddingEnabled: false,  // free tier default
  }
}
```

### 6. `src/shared/constants.js` — 加 freemium 常數
- `FREEMIUM_FACT_LIMIT = 500`
- `FREEMIUM_DAILY_EXTRACT_LIMIT = 50`
- 用於 config 未設定時的 fallback

### 7. `src/license/license-state.js` — 新模組，集中授權狀態
- `async function getLicenseState()` → `{ licensed, tier, expiry, machineId }`
- 快取結果（啟動時算一次）
- `isLicensed()` 簡便查詢
- Worker / store / CLI 統一從這裡查詢

### 8. `src/worker/store.js` — facts 上限 + 覆寫最冷
- `storeFacts()` 開頭：如果 `!isLicensed()`，查 active facts count
- 超過 `factLimit` 時：找 `heat` 最低 + `decay_bucket = 'cold'` 的 fact
- 將其 status → 'evicted'，對應 embedding 也刪除
- `saveFactManually()` 同理

### 9. `src/worker/worker.js` — 每日萃取上限 + embedding 條件
- `pollQueue()`: 維護 `dailyExtractCount` + `lastExtractDate`
- 超過 `dailyExtractLimit` → skip（log warning，不移到 dead-letter）
- `processFile()` L119-123: `if (!isLicensed()) skip storeEmbeddings()`

### 10. `bin/kiroku.js` — CLI 增強
- **`cmdStart()`**: 開頭加 license check，未授權顯示 gentle reminder：
  ```
  ⚠ Kiroku is running in free mode (500 facts, no vector search)
    Machine ID: 3A7F1B2C9E0D4F58
    Activate: https://kiroku.dev/activate
  ```
- **`cmdDoctor()`**: 擴展顯示 machine-id、tier、expiry
- **`cmdInit()`**: 建立 `.claude/commands/kiroku-id.md`
- 所有呼叫 `verifyLicense()` / `getMachineId()` 改為 `await`

## 驗證

1. `node scripts/gen-keypair.js` → keys/public.pem + keys/private.pem
2. `node scripts/sign-license.js <mid>` → 產生 license.dat
3. `kiroku doctor` → 顯示 machine-id、license valid
4. 無 license 時：
   - `kiroku start` 顯示 gentle reminder
   - 萃取正常但不產生 embedding
   - facts 超過 500 時覆寫最冷的
   - 每日第 51 次萃取被 skip
5. 有 license 時：所有限制解除

## 未解決問題

- `https://kiroku.dev/activate` URL 尚不存在，先用 placeholder
- `heat` / `decay_bucket` 目前所有 fact 都是 0.5/warm，覆寫邏輯需要 fallback 到 oldest
